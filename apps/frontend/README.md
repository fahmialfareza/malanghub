## Getting Started

First, run the development server:

```bash
npm run dev
# or
yarn dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to see the result.

You can start editing the page by modifying `pages/index.js`. The page auto-updates as you edit the file.

[API routes](https://nextjs.org/docs/api-routes/introduction) can be accessed on [http://localhost:3000/api/hello](http://localhost:3000/api/hello). This endpoint can be edited in `pages/api/hello.js`.

The `pages/api` directory is mapped to `/api/*`. Files in this directory are treated as [API routes](https://nextjs.org/docs/api-routes/introduction) instead of React pages.

## Deploy on Cloudflare Pages (static export)

The site is a static export (`output: "export"` in `next.config.js`) served by Cloudflare Pages as plain files. No Worker or Pages Function runs, so there are no CPU limits to hit.

```bash
pnpm pages:build    # next build + scripts/generate-seo-files.mts → out/
pnpm pages:preview  # build, then serve out/ with `wrangler pages dev` (http://localhost:8788)
pnpm pages:deploy   # build and deploy to Pages project `malanghub` (needs `wrangler login`)
```

How content gets to the site:

- Article, category, tag, author and listing pages are prerendered with `getStaticProps`/`getStaticPaths` from `API_ADDRESS`. Any API failure fails the build, so the previous deploy stays live.
- `.github/workflows/frontend-pages.yml` rebuilds and deploys:
  - on push to `main`;
  - on a `content-changed` repository dispatch, sent by the backend (`apps/backend/pkg/sitebuild`) when news, categories, tags or an author's profile change;
  - every 6 hours, to refresh trending lists and the Google News sitemap.
- After deploying, the workflow diffs the new `sitemap.xml` against the previously live one and pings IndexNow for the changed URLs.
- Page 2+ of listings (`?page=N`), search (`/search/*`), draft previews and the `/users` dashboard load in the browser. `public/_redirects` serves the search and draft shells for every URL under them.
- `sitemap.xml`, `news-sitemap.xml`, `feed.xml`, `llms.txt` and the IndexNow key file are generated by `scripts/generate-seo-files.mts` (`utils/seoFiles.ts`).
- Security headers are set in `public/_headers`. The `malanghub.com` → `www` redirect is a Cloudflare Redirect Rule, not app code.
- `next/image` uses `utils/imageLoader.ts`: Cloudinary images are resized by Cloudinary, everything else is served as-is.

Configuration:

- **GitHub Actions secrets:** `NEXT_PUBLIC_*`, `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT`, `CLOUDFLARE_API_TOKEN` (Cloudflare Pages: Edit) and `CLOUDFLARE_ACCOUNT_ID`. `API_ADDRESS` reuses `NEXT_PUBLIC_API_ADDRESS`.
- **Backend (Railway):** set `GITHUB_DISPATCH_TOKEN`, a fine-grained PAT for this repo with *Contents: read and write* (needed for repository dispatch). `GITHUB_REPO` defaults to `fahmialfareza/malanghub`.
- Pages' own Git builds must stay off; deploys come from the workflow.
